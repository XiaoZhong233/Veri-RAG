# 会话记忆配置与部署

本次统一正式回答的两种历史传递方式：原生 ChatMemory 与手动文本历史共用
ConversationContextService。数据库完整记录不删除，不引入结构化客户需求表。

## 配置

服务器 `.env` 应更新为：

```dotenv
RAG_MEMORY_ENABLED=true
RAG_MEMORY_RECENT_MESSAGES=8
RAG_MEMORY_SUMMARY_TRIGGER_MESSAGES=2
RAG_MEMORY_MAX_CONTEXT_MESSAGES=16
RAG_MEMORY_MAX_CONTEXT_CHARS=8000
```

`RAG_HISTORY_MAX_MESSAGES` 已移除，历史窗口统一由 `RAG_MEMORY_RECENT_MESSAGES` 控制。
`RAG_MANUAL_HISTORY_ENABLED` 仍只决定角色消息/文本拼接两种格式，不再影响历史窗口大小。
旧服务器显式设置的摘要阈值 `12` 会覆盖默认值，需手动改为 `2` 后重新创建应用容器。
本地 `.env` 已同步，仅改上述记忆配置；它不会随 Git 部署。

## 读取和生成

- 原始窗口默认8条（约4轮），超过窗口的未压缩消息累计2条后生成摘要。
- 首次10条时，压缩前2条，保留后8条；此后按同样方式增量合并。
- 摘要异步成功前，原摘要与摘要边界之后的原文一起读取；成功后切换至更新的摘要。
- 窗口允许临时扩展至16条，原文正文累计最多8000个Java字符单位，最新优先。
  超长消息只截取模型输入副本，不修改数据库。超限时可能丢弃较早的待压缩内容，不承诺无限记忆。
- 摘要失败或返回空值时不更新压缩进度，后续回答完成后再尝试。
- 摘要和原文在一个只读可重复读事务中读取，避免一次读取混用两个摘要进度。
- 不以日期清空会话，隔天仍按同一会话读取；用户主动新建会话则不继承旧会话。

## 需求与动作

摘要提示明确保存预算、日期、租期、学校、当前意向等咨询事实，用户更新时替换旧值。
明确删除转人工、取消转接、结束接待等旧操作指令；原始历史也附带“不是当前操作授权”的说明。
真实转接仍经过已有的当前消息独立确认，不依靠摘要执行动作。
摘要更新依赖实际模型遵循提示词，并非结构化字段的确定性覆盖。
旧摘要会在后续摘要成功时逐步清理，本次不批量改写已有数据。

## 验证

补充了等待摘要期间的早期预算保留、修改预算原文顺序、摘要边界切换、条数/长度上限、
原生历史配置复用、摘要失败后不推进且可重试，以及摘要提示规则的测试代码。
测试中的预算/公寓更新使用模拟模型输出，不等于已验证真实模型语义准确率。
遵照要求未执行 Maven 编译或 Java 测试，也未部署线上。
上线后应实测预算修改、公寓切换、隔天咨询及退出人工后继续找房。
