# 客户会话工作区

入口：管理后台 → 客服管理 → 客户会话。所有新增接口沿用该控制器的 ADMIN 权限，
普通用户不能通过接口获取客户资料、聊天记录或服务摘要。

## 功能与范围

- 分客服账号列出客户，按已缓存昵称或客户标识搜索，30条一页。
- 当前页按需批量拉取微信昵称、头像，并缓存24小时；可单独刷新资料。
  使用微信客服 secret 对应的 token 调用 `/cgi-bin/kf/customer/batchget`，不是通讯录 secret。
  不采集手机号、微信号、UnionID 等非展示必需字段。昵称不是验证过的真实姓名。
- 头像仅通过 HTTPS 展示，HTTP地址尝试升级HTTPS，加载失败显示昵称首字；不向浏览器提供 access_token。
- 客户记录使用“客服账号＋external_userid”关联，同一客户在不同客服账号下分别展示，避免混合不同服务上下文。
- 微信消息每页50条，支持加载更早记录。显示客户、人工、机器人和系统角色。
  客户/人工消息从 sync_msg 可返回内容中留存；本系统成功发送的文字、欢迎语和转接提示也会留存。
  非文字内容仅显示类型，不下载头像以外的客户媒体，也不提供媒体内容识别。
- 消息以微信 msgid 去重。同步消息留存在游标推进前，失败可重新同步；已发送消息如存档失败，
  不重复发送，日志记录 `wecom.kf.outbound_archive_failed`，需要运维核查。

## 历史限制

建表时从已有 `kf:` 会话映射导入客户标识。昵称、头像仍需微信接口授权及资料可用。
旧的机器人问答通过“历史机器人记录”读取现有映射关联的会话；历史片段截止于首条归档微信消息之前。
不会声称已恢复所有历史人工聊天；仅能展示微信接口实际同步到并留存的内容。
原会话若已删除或映射被替换，对应旧问答不会凭空恢复。
客户已经转人工、但尚未产生本地 RAG 会话的，也可在新消息同步后出现在列表中。

## 服务摘要

“生成／更新摘要”为人工主动操作，使用现有摘要模型客户端，不在每条客户消息上额外调用模型。
该摘要独立保存在客户表，不修改机器人记忆，也不发送给客户、不触发转人工或预订。
输入范围为已有服务摘要、会话记忆摘要、最多50条历史机器人记录及100条新微信消息，
原始片段限制为最近16000字符。页面标明生成依据截至时间，新消息需要再次更新摘要。
摘要包括：找房需求、当前关注公寓、已沟通事项、待确认问题、建议跟进。
新条件覆盖旧条件；未提供的信息不猜测；助手推荐不当作客户确认；历史转人工不作为待执行动作。
模型失败保留旧摘要。同一实例同一客户禁止并发生成；不提供多实例分布式锁。
AI摘要需人工核实，不保证涵盖全部历史，也不代替真实合同或库存信息。

## 部署与验证

新增两张表在默认启动 SQL 初始化中幂等创建：
`t_wecom_kf_customer`、`t_wecom_kf_customer_message`。
若禁用了初始化，需要先执行 `schema.sql` 中对应建表及客户导入语句。
客户数据属于内部服务资料，需要纳入现有数据库访问、备份和保留期限管理；本次不自动删除历史数据。

已用虚构数据检查桌面和390px手机宽度的客户列表、摘要及消息显示，并通过前端JS语法和diff检查。
补充了权限注解、资料失败回退、消息角色、历史顺序、头像地址及摘要不发送的Java测试代码。
遵照项目要求未执行 Maven 编译/Java测试；未验证真实微信权限、真实模型输出或生产数据库迁移。
上线后应验证昵称头像获取、实际人工消息是否被微信同步返回，以及新旧记录衔接。
